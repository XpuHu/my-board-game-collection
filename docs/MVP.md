# Board Game Collection MVP

**Версия:** 2.1  
**Статус:** Draft

---

# 1. Цель MVP

MVP должен дать пользователю рабочий инструмент для двух разных задач:

* быстро управлять играми, которые уже есть в коллекции;
* подробно изучать игры, которые хочется попробовать или купить.

Первая версия считается готовой, если пользователь может вести коллекцию, wishlist, предзаказы и историю партий, а также синхронизировать партии с BoardGameGeek.

Данные MVP строятся вокруг `Item` и `UserItem`: `Item` хранит локальный кэш справочной информации, а `UserItem` хранит состояние конкретного пользователя для этого `Item`.

Основные флоу MVP:

1. Добавить партию.
2. Изменить предзаказ.
3. Добавить игру в коллекцию.
4. Добавить игру в wishlist.

---

# 2. Пользовательские сценарии

## MVP-01. Главная с быстрыми действиями

**Как пользователь**, я хочу видеть ближайшие полезные действия, чтобы быстро перейти к ежедневным сценариям.

Основной поток:

1. Пользователь открывает главную.
2. Видит блок "Сегодня можно сыграть".
3. Видит ближайшие предзаказы.
4. Видит последние партии.
5. Видит быстрые действия.

Критерии готовности:

* на главной есть действия "Добавить партию", "Изменить предзаказ", "Добавить игру";
* ближайший предзаказ можно открыть на изменение даты;
* последнюю партию можно открыть из списка.

---

## MVP-02. Компактная коллекция

**Как пользователь**, я хочу видеть список своих игр без лишней справочной информации, чтобы быстро понимать, во что я играю.

Основной поток:

1. Пользователь открывает "Моя коллекция".
2. Приложение показывает только `Item` с `owned = true`.
3. Каждый элемент показывает название, личную оценку, количество партий и дату последней партии.
4. Пользователь открывает компактную карточку.

Критерии готовности:

* список отображает пустое и заполненное состояние;
* в списке нет длинного описания игры;
* доступны поиск и базовые фильтры по коллекции;
* карточка работает для разных типов `Item`.

---

## MVP-03. Подробный wishlist

**Как пользователь**, я хочу подробно изучить игру перед покупкой, чтобы принять решение.

Основной поток:

1. Пользователь открывает Wishlist.
2. Видит игры с `wishlist = true`.
3. Открывает подробную карточку.
4. Видит описание, характеристики, изображения, механики, категории, авторов, рейтинги и внешние ссылки.
5. Может добавить игру в коллекцию или оформить предзаказ.

Критерии готовности:

* wishlist визуально и информационно отличается от коллекции;
* карточка wishlist показывает максимум справочной информации;
* есть кнопки "Добавить в коллекцию" и "Оформить предзаказ".

---

## MVP-04. Поиск во внешних источниках

**Как пользователь**, я хочу найти игру во внешних источниках, чтобы не вводить справочные данные вручную.

Основной поток:

1. Пользователь вводит название или ссылку.
2. Приложение ищет совпадения в подключенных источниках.
3. Пользователь видит результаты.
4. Каждый результат показывает название, источник, год, изображение и ссылку, если они доступны.

Критерии готовности:

* поиск возвращает результаты хотя бы из одного источника;
* результат содержит внешний источник и внешний идентификатор;
* ошибка источника показывается понятным предупреждением.

---

## MVP-05. Добавление игры в коллекцию

**Как пользователь**, я хочу добавить игру в свою коллекцию, чтобы учитывать владение, партии и покупки.

Основной поток:

1. Пользователь нажимает "Добавить игру".
2. Находит игру во внешнем источнике или выбирает ручное создание.
3. Приложение загружает справочные данные.
4. Создает или обновляет `Item`.
5. Устанавливает `owned = true`.
6. Пользователь при необходимости добавляет покупку, место хранения, личную оценку и заметки.
7. Приложение открывает компактную карточку коллекции.

Критерии готовности:

* импортированный элемент хранится как `Item`;
* справочные поля `Item` и пользовательское состояние `UserItem` разделены;
* если игра уже была в wishlist, она не дублируется;
* элемент появляется в "Моей коллекции".

---

## MVP-06. Добавление игры в wishlist

**Как пользователь**, я хочу добавить игру в wishlist, чтобы вернуться к ней позже и принять решение.

Основной поток:

1. Пользователь ищет игру.
2. Открывает подробную карточку.
3. Нажимает "Добавить в wishlist".
4. Приложение создает или обновляет `Item`.
5. Устанавливает `wishlist = true`.
6. Игра появляется в Wishlist.

Критерии готовности:

* wishlist-элемент может не быть owned;
* внешний идентификатор сохраняется для синхронизации;
* карточка wishlist доступна сразу после добавления.

---

## MVP-07. Компактная карточка коллекции

**Как пользователь**, я хочу открыть свою игру и видеть только важное для владельца, чтобы быстро совершить действие.

Основной поток:

1. Пользователь открывает игру из коллекции.
2. Видит личную оценку, наличие, последнюю партию, всего партий, стоимость, заметки и активный предзаказ.
3. Нажимает "Добавить партию".
4. При необходимости открывает справочную информацию отдельным действием.

Критерии готовности:

* главное действие карточки - "Добавить партию";
* длинная справочная информация не мешает основному экрану;
* пользовательские данные редактируются отдельно от справочных.

---

## MVP-08. Добавление партии

**Как пользователь**, я хочу быстро добавить партию, чтобы вести историю игр.

Основной поток:

1. Пользователь нажимает "Добавить партию".
2. Выбирает игру, если она не задана контекстом.
3. Заполняет дату, количество игроков, длительность, результат и заметки.
4. При необходимости указывает дополнения.
5. Сохраняет партию.
6. Приложение обновляет счетчик партий и дату последней партии.

Критерии готовности:

* форму можно заполнить в одном окне;
* партия привязана к `Item`;
* карточка и список коллекции обновляют агрегаты;
* партия видна в истории партий.

---

## MVP-09. История партий

**Как пользователь**, я хочу видеть историю партий по игре и в общем списке, чтобы помнить, во что и когда играл.

Основной поток:

1. Пользователь открывает раздел "Партии" или историю в карточке игры.
2. Видит список партий.
3. Открывает запись.
4. Изменяет локальные данные.
5. Сохраняет изменения.

Критерии готовности:

* история работает по всем партиям и по конкретной игре;
* запись партии можно открыть и изменить;
* список показывает дату, игроков, результат и длительность.

---

## MVP-10. Синхронизация партий с BGG

**Как пользователь**, я хочу импортировать партии из BoardGameGeek, чтобы не переносить историю вручную.

Основной поток:

1. Пользователь указывает BGG username в настройках.
2. Запускает синхронизацию партий.
3. Приложение получает партии из BGG.
4. Сопоставляет их с локальными `Item` по внешним идентификаторам.
5. Создает недостающие партии.
6. Не создает дубли при повторном запуске.
7. Показывает результат синхронизации.

Критерии готовности:

* у импортированной партии хранится `bggPlayId`;
* повторная синхронизация не дублирует партии;
* локально измененные пользовательские поля не перезаписываются без правила;
* ошибки BGG показываются пользователю.

---

## MVP-11. Предзаказы

**Как пользователь**, я хочу видеть активные предзаказы и быстро менять дату доставки.

Основной поток:

1. Пользователь открывает "Предзаказы".
2. Видит список активных предзаказов.
3. Нажимает действие изменения даты.
4. Меняет ожидаемую дату.
5. При необходимости указывает причину.
6. Сохраняет изменение.

Критерии готовности:

* изменение даты открывается быстрым окном;
* предзаказ связан с `Item`;
* изменение даты сохраняет событие в истории;
* ближайшие предзаказы видны на главной.

---

## MVP-12. Оформление предзаказа из wishlist

**Как пользователь**, я хочу оформить предзаказ из wishlist, чтобы отслеживать ожидаемую игру.

Основной поток:

1. Пользователь открывает карточку wishlist.
2. Нажимает "Оформить предзаказ".
3. Указывает магазин, стоимость, дату заказа, ожидаемую дату и статус.
4. Сохраняет предзаказ.
5. Игра получает состояние `preordered`.

Критерии готовности:

* предзаказ виден в общем списке;
* элемент может оставаться в wishlist до получения;
* стоимость предзаказов учитывается в статистике.

---

## MVP-13. Редактирование пользовательских данных

**Как пользователь**, я хочу редактировать личные данные игры, чтобы коллекция отражала реальность.

Основной поток:

1. Пользователь открывает карточку коллекции.
2. Изменяет наличие, место хранения, личную оценку, заметки или теги.
3. Сохраняет изменения.

Критерии готовности:

* справочные поля `Item` не меняются;
* изменения сохраняются после перезагрузки;
* сценарий работает для любого типа `Item`.

---

## MVP-14. Синхронизация справочных данных

**Как пользователь**, я хочу обновить справочные данные игры, чтобы карточка оставалась актуальной.

Основной поток:

1. Пользователь открывает подробную справочную карточку.
2. Нажимает "Обновить данные".
3. Приложение получает данные из внешних источников.
4. Обновляет только справочную часть.
5. Показывает дату последней синхронизации.

Критерии готовности:

* `UserItem`, партии и предзаказы не изменяются;
* внешние идентификаторы используются для повторной синхронизации;
* при ошибке пользователь видит понятное сообщение.

---

## MVP-15. Статистика

**Как пользователь**, я хочу видеть статистику партий и коллекции, чтобы понимать свои игровые привычки.

Основной поток:

1. Пользователь открывает "Статистика".
2. Видит всего партий.
3. Видит партии за текущий месяц.
4. Видит любимую и самые частые игры.
5. Видит стоимость коллекции и предзаказов.

Критерии готовности:

* статистика строится по локальной истории партий;
* импортированные из BGG партии учитываются;
* игры без цены не ломают расчеты.

---

## MVP-16. JSON импорт и экспорт

**Как пользователь**, я хочу экспортировать и импортировать данные, чтобы иметь резервную копию.

Критерии готовности:

* экспорт включает `Item`, `UserItem`, wishlist, покупки, предзаказы, историю изменений предзаказов, партии, связи, ссылки и теги;
* импорт не создает дубли внешних идентификаторов и BGG партий;
* пользователь видит отчет об импорте.

---

# 3. Что не входит в MVP

В MVP не входят:

* полноценное сравнение цен между магазинами;
* уведомления о прибытии предзаказов;
* облачная синхронизация;
* несколько пользователей;
* мобильное приложение;
* автоматическое объединение спорных дублей без подтверждения;
* продвинутые рекомендации игр;
* полноценный календарь релизов.

---

# 4. Приоритет реализации

Рекомендуемый порядок:

1. База данных: `Item`, `UserItem`, партии, предзаказы.
2. Компактная коллекция и карточка коллекции.
3. Добавление партии и история партий.
4. Предзаказы и быстрое изменение даты.
5. Внешний поиск и добавление в коллекцию.
6. Wishlist и подробная карточка.
7. BGG sync для партий.
8. Синхронизация справочных данных.
9. Статистика.
10. JSON импорт и экспорт.
