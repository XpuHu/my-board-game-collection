# UI_LAYOUT.md

# Board Game Collection — технический макет интерфейса

**Версия:** 1.1  
**Назначение:** документ для реализации интерфейса в Codex  
**Референс:** тёмный dashboard-интерфейс с карточками, левой навигацией, фиолетовыми акцентами и плотной информационной компоновкой.

---

# 1. Цель документа

Документ описывает структуру страниц, визуальные правила, компоненты, состояния и адаптивное поведение приложения.

Codex должен использовать документ как источник требований для вёрстки. При реализации следует сохранять:

- тёмную цветовую схему;
- левую фиксированную навигацию;
- карточную компоновку;
- скруглённые панели;
- слабые границы вместо выраженных теней;
- фиолетовый цвет для основных действий;
- компактное представление данных;
- крупные обложки игр как главный визуальный элемент.

Документ не задаёт конкретный frontend-фреймворк. Рекомендуемый стек:

- React;
- TypeScript;
- CSS Modules, Tailwind CSS или styled-components;
- компонентная архитектура;
- SVG-иконки;
- адаптивная grid-сетка.

# 3. Sidebar

Sidebar фиксируется слева на desktop.

```text
┌────────────────────────┐
│ Logo + app name        │
│                        │
│ Главная                │
│ Моя коллекция          │
│ Wishlist               │
│ Предзаказы             │
│ Партии                 │
│ Статистика             │
│ Настройки              │
│                        │
│                        │
│ powered_by_bgg.webp    │
└────────────────────────┘
```

## 3.1 Верхняя часть

- логотип 32×32 px;
- название приложения в две строки;
- высота блока около 72 px;
- внутренний отступ 20 px.

## 3.2 Навигационный пункт

```text
[icon 20×20]  Label
```

Состояния:

- default;
- hover;
- active;
- focus-visible.

Active item:

- фон `--accent-soft`;
- текст `--text-primary`;
- иконка `--accent-primary`;
- border-radius 8 px.

Высота пункта: 44 px.

## 3.3 Нижняя часть sidebar

Вместо блока пользователя внизу размещается готовое изображение
`powered_by_bgg.webp` из корня репозитория. В sidebar не должно быть аватара,
имени, роли, chevron или других элементов профиля.

Требования к BGG attribution:

- блок прижат к нижней части sidebar через `margin-top: auto`;
- внутренние отступы 20 px, выравнивание по левому краю;
- изображение занимает до 168 px по ширине, высота — `auto`;
- сохранять исходные пропорции, `object-fit: contain`;
- alt-текст: `Powered by BoardGameGeek`;
- не добавлять вокруг логотипа карточку, фон, разделитель или подпись.

# 4.8 SidebarBggAttribution

Общий компонент для логотипа BGG в нижней части sidebar. Использует только
готовое изображение `powered_by_bgg.webp`; логотип нельзя перерисовывать
текстом, SVG или CSS. Файл следует импортировать или разместить в
публичной директории сборщика без изменения самого изображения. Размеры и
отступы заданы в разделе 3.3.

# 5. Страница «Главная»

Route:

```text
/
```

Основная задача страницы:

- показать последние партии;
- дать быстрый доступ к изменению даты предзаказа;
- показать краткую статистику;
- показать недавно добавленные игры;
- показать любимую игру и активность по дням;
- дать быстрые действия;
- показать цитату дня.

PageHeader соответствует референсу:

```text
Главная                                      [Поиск] [Уведомления]
```

- заголовок и приветствие выровнены слева;
- справа расположены две квадратные icon-only кнопки 40×40 px;
- порядок кнопок: поиск, уведомления;
- у уведомлений расположен круглый badge со счётчиком в правом верхнем углу;
- в mock-состоянии референса счётчик уведомлений равен `3`;
- имя в приветствии подставляется из данных, но не создаёт профиль в sidebar;
- отступ от приветствия до первой строки панелей — 18–20 px.

## 5.1 Grid desktop

Использовать 12-колоночную grid-сетку.

```text
Row 1:
┌─────────────────┬─────────────────┬──────────────────────┐
│ Последние       │ Ближайшие       │ Недавно добавленные │
│ партии          │ предзаказы      │ в коллекцию          │
│ 4 cols          │ 4 cols          │ 4 cols               │
└─────────────────┴─────────────────┴──────────────────────┘

Row 2:
┌──────────────────────────┬──────────────┬─────────────────┐
│ Статистика за <месяц>    │ Любимая     │ Активность      │
│ 6 cols                   │ игра        │ по дням         │
│                          │ 3 cols      │ 3 cols          │
└──────────────────────────┴──────────────┴─────────────────┘

Row 3:
┌──────────────────────┬────────────────────────────────────┐
│ Быстрые действия     │ Цитата дня                         │
│ 5 cols               │ 7 cols                             │
└──────────────────────┴────────────────────────────────────┘

```

Высоты панелей внутри одной строки выравниваются. Горизонтальный gap — 16 px,
между строками — 18 px. Между PageHeader и первой строкой — 20 px. Третья
строка завершает dashboard; отдельного footer или дублирующегося логотипа BGG
в контентной области нет.

Для desktop-референса шириной 1536 px ориентировочная высота первой строки —
460 px, второй и третьей — по 190 px. Панели имеют padding 20 px. Заголовок
панели и действие «Смотреть все» находятся в одной строке; действие выровнено
по правому краю и использует `--accent-primary`. При длинном контенте панель
может стать выше, обрезать текст нельзя.

## 5.2 Последние партии

Компонент:

```ts
type RecentPlay = {
  id: string;
  gameId: string;
  title: string;
  coverUrl: string;
  playedAt: string;
  playersCount: number;
  durationMinutes: number;
  result: "win" | "loss" | "other";
};
```

В заголовке панели расположена ссылка «Смотреть все». Отображать 4 последние
партии, новые сверху. Между заголовком панели и списком — 16 px, между
строками — 14 px.

Каждая запись — самостоятельная компактная карточка высотой около 80 px с
тонкой границей и радиусом 8 px. Квадратная обложка 76×76 px примыкает к
левому краю строки и имеет скругление только в пределах карточки.

Строка:

```text
[cover]  Title                              relative date
         [players icon] players  [clock icon] duration  [result badge]
```

Название занимает оставшееся пространство и выделено полужирным. Относительная
дата расположена справа сверху и использует вторичный цвет. Количество игроков,
продолжительность и результат находятся в нижней строке. Результат показывается
через `StatusBadge`: победа — `success`, поражение — `danger`.

Контент референса:

| Игра | Дата | Игроки | Время | Результат |
|---|---|---:|---:|---|
| Spirit Island | вчера | 2 игрока | 95 мин | Победа |
| Ark Nova | 3 дня назад | 3 игрока | 120 мин | Победа |
| Gloomhaven | 5 дней назад | 4 игрока | 150 мин | Поражение |
| Brass: Birmingham | неделю назад | 2 игрока | 90 мин | Победа |

Действия:

- клик по строке открывает партию;
- «Смотреть все» ведёт на `/plays`;
- контекстное меню необязательно для MVP.

## 5.3 Ближайшие предзаказы

```ts
type UpcomingPreorder = {
  id: string;
  itemId: string;
  title: string;
  coverUrl: string;
  store: string;
  expectedDate: string;
  status: "active" | "delayed" | "received" | "cancelled";
};
```

В заголовке панели расположена ссылка «Смотреть все». Отображать 3 записи,
сортировать по ближайшей ожидаемой дате. Записи не имеют общей внутренней
рамки и разделяются вертикальными отступами.

Структура записи:

```text
[month] [cover]  title
                 store
                 Ожидается
                 formatted date
                 [Изменить дату]
```

Слева находится календарный блок фиксированной ширины с сокращённым названием
месяца в цвете `--accent-primary`. День месяца не отображается. Далее —
вертикальная обложка 92×108 px. Справа последовательно расположены название,
магазин, подпись «Ожидается», дата в формате «месяц год» и компактная
фиолетовая кнопка «Изменить дату». Длинное название может занимать две строки.

Контент референса:

| Дата | Игра | Магазин |
|---|---|---|
| август 2025 | Frosthaven | CrowdRepublic |
| сентябрь 2025 | Nemesis: Retaliation | Gamefound |
| октябрь 2025 | Deep Rock Galactic: The Board Game | CrowdRepublic |

Кнопка «Изменить дату» открывает `EditPreorderDateModal`, ссылка «Смотреть все»

## 5.4 Недавно добавленные в коллекцию

В заголовке панели расположена ссылка «Смотреть все», ведущая на
`/collection`. Отображение 2×2, всего 4 карточки. Между карточками — 12 px.

Каждая карточка:

- имеет соотношение сторон около 1.15 / 1 и радиус 8 px;
- использует обложку как изображение на всю площадь с `object-fit: cover`;
- имеет затемняющий градиент снизу, достаточный для контраста текста;
- показывает внизу название, относительную дату добавления и пятизвёздочный

Название располагается максимум в две строки, рейтинг — у нижнего края.
Заполненные звёзды здесь используют `--warning`.

## 5.5 Статистика за месяц

Заголовок содержит текущий месяц в нижнем регистре: например, «Статистика за
июль». В панели находятся пять одинаковых по ширине метрик:

```text
icon
value
label
```

Метрики:

- количество партий;
- количество разных игр;
- общее время;
- средняя личная оценка;
- количество побед.

Метрики располагаются в одну строку, имеют одинаковую ширину и разделяются
тонкими вертикальными линиями `--border-subtle`. Иконка расположена в мягком
цветном круге; у каждой метрики свой акцент. Значение набрано крупно, подпись
находится под ним.

Контент референса:

| Значение | Подпись |
|---:|---|
| 14 | партий |
| 7 | разных игр |
| 26 ч | наиграно |
| 4.2 | ср. оценка |
| 5 | побед |

## 5.7 Активность по дням

Heatmap активности за последний период.

Требования:

- над сеткой подписи дней недели: «Пн»—«Вс»;
- данные группируются в 7 визуальных колонок по дням недели;
- под каждой подписью показывается несколько ячеек последних периодов;
- квадратные ячейки с gap 3–4 px;
- пустое состояние ячейки и 5 уровней фиолетовой интенсивности;
- tooltip с датой и количеством партий;
- под сеткой расположена легенда: слева «Меньше», затем шкала интенсивности,
  справа «Больше».

Для MVP можно использовать статический CSS Grid.

## 5.8 Быстрые действия

Четыре плитки:

- Добавить партию;
- Добавить игру;
- Изменить предзаказ;
- Добавить фото.

Каждая плитка:

- занимает равную долю в сетке из 4 колонок;
- имеет высоту около 116 px и радиус 8 px;
- содержит крупную контурную иконку сверху и подпись в 1–2 строки снизу;
- имеет собственные цвет рамки и мягкий полупрозрачный фон: фиолетовый,
  синий, зелёный и янтарный соответственно;
- hover с поднятием на 2 px;
- keyboard focus.

Действия ведут соответственно к добавлению партии, добавлению элемента
коллекции, выбору предзаказа для изменения и добавлению фото.

## 5.9 Цитата дня

Широкая информационная панель из референса:

```text
Цитата дня

“
Текст цитаты в 1–2 строки.

— Автор
```

Требования:

- панель занимает 7 колонок и имеет ту же высоту, что «Быстрые действия»;
- текстовая область занимает левую часть панели;
- справа размещается декоративное фоновое изображение настольной игры;
- поверх изображения используется градиент от `--bg-surface` к прозрачному,
  чтобы текст сохранял контраст;
- знак цитаты выделяется `--accent-primary`, автор — тёплым акцентом;
- изображение декоративное и не должно получать фокус;
- при отсутствии изображения показывается обычная панель без пустого
  placeholder.

Контент референса:

```text
Нет такой плохой игры, которая не стала бы лучше
после хорошей партии.

— Том Вассел
```

# 6. Страница «Моя коллекция»

Route:

```text
/collection
```

Главное представление — сетка крупных карточек игр. Референс этого раздела
определяет композицию и плотность контента, но не меняет цветовую систему:
фон страницы, поверхности, границы, текст, статусы и акценты должны использовать
переменные из раздела 2.2.

Заголовок страницы:

```text
Моя коллекция
```

- заголовок расположен отдельно над toolbar, без подзаголовка;
- размер и начертание соответствуют общему `PageHeader`;
- между заголовком и toolbar — 24–28 px;
- между toolbar и сеткой — 28–32 px.

---

## 6.1 Toolbar

```text
[🔍 Поиск по коллекции...]  [Все 128] [Игры 84] [Дополнения 28] [Аксессуары 16]  Сортировка: Недавние партии⌄  [+ Добавить игру]
```

На desktop все элементы находятся в одной строке:

- поле поиска стоит первым, имеет ширину 320–340 px и высоту 44 px;
- после поиска расположен segmented control с четырьмя вкладками;
- внутри каждой вкладки справа от подписи показан числовой счётчик;
- активная вкладка «Все» использует `--accent-soft` и
  `--accent-primary`, остальные — обычную поверхность и вторичный текст;
- блок сортировки прижат вправо через свободное пространство;
- сортировка выглядит как компактный текстовый control без отдельной
  крупной панели: muted-подпись «Сортировка:», текущее значение и chevron;
- primary-кнопка «+ Добавить игру» завершает строку;
- отдельная кнопка «Фильтры» в основном desktop-состоянии не показывается.

Размеры и расстояния:

| Элемент | Значение |
|---|---:|
| Высота toolbar controls | 44 px |
| Gap между поиском и вкладками | 18–20 px |
| Gap между вкладками | 4 px |
| Горизонтальный padding вкладки | 14–16 px |
| Gap перед primary action | 20–24 px |

Вкладки фильтруют коллекцию по типу:

- «Все»;
- «Игры»;
- «Дополнения»;
- «Аксессуары».

Поддерживаемые варианты сортировки:

- недавние партии;
- давно не играли;
- количество партий;
- личная оценка;
- название.

Поиск, активная вкладка и сортировка синхронизируются с URL query params.

## 6.2 Сетка карточек

На широком desktop сетка состоит из четырёх равных колонок. Карточка добавления
игры занимает обычную ячейку сетки.

```css
.collection-grid {
  display: grid;
  grid-template-columns: repeat(4, minmax(0, 1fr));
  gap: 28px 24px;
}
```

- целевая ширина карточки на desktop — 300–350 px;
- все карточки в строке имеют одинаковую высоту;
- минимальная ширина карточки — 240 px;
- при недостаточной ширине количество колонок уменьшается до трёх, затем до
  двух и одной без горизонтального скролла.

---

## 6.3 CollectionCard

Карточка имеет две зоны: крупную media-зону со всей игровой статистикой и
компактный нижний footer. Вся карточка кликабельна и открывает страницу игры,
но вложенные кнопки выполняют собственные действия.

### Верхняя media-зона

- занимает примерно 82–84% высоты карточки;
- минимальная высота на desktop — 300 px;
- использует обложку или горизонтальное изображение как фон с
  `background-size: cover`;
- поверх изображения обязателен градиент: лёгкое затемнение сверху для
  заголовка и более плотное снизу для статистики;
- название расположено слева сверху, в одну строку с ellipsis при переполнении;
- справа сверху находится круглая icon-only кнопка быстрого добавления партии;
- под названием расположен личный рейтинг из пяти звёзд;
- ниже рейтинга показан компактный badge последней партии;
- в нижней части расположено крупное количество партий;
- последняя строка содержит игроков, среднюю/последнюю длительность и результат
  последней партии;
- метаданные сопровождаются компактными иконками: игроки, часы, кубок;
- победа использует `--success`, поражение — `--danger`; результат всегда
  содержит текст и не кодируется только цветом.

```text
Spirit Island                                      [(+)]
★★★★★
[Играли вчера]

42
партии

♟ 2 игрока       ◷ 95 мин       ♜ Победа
```

Badge последней партии:

- «Играли вчера» — `--success-soft`;
- «3 дня назад» — `--warning-soft`;
- более старые даты — нейтральная поверхность;
- если партий ещё не было — «Ещё не играли» на нейтральной поверхности.

### Нижний footer

- высота 60–64 px;
- фон `--bg-surface`, отделён от media-зоны границей `--border-subtle`;
- слева показано количество дополнений, если оно известно;
- рядом показано количество фото;
- overflow menu прижат к правому краю;
- отсутствующее значение дополнений обозначается длинным тире;
- кнопки «+ Партия» в footer нет: быстрое добавление партии выполняет
  icon-only кнопка в правом верхнем углу media-зоны.

```text
3 дополнения     ▣ 18 фото                              […]
```

| Игра | Последняя партия | Партии | Игроки | Время | Результат | Дополнения | Фото |
|---|---|---:|---|---:|---|---:|---:|
| Spirit Island | Играли вчера | 42 | 2 игрока | 95 мин | Победа | 3 | 18 |
| Ark Nova | 3 дня назад | 31 | 3 игрока | 120 мин | Победа | 2 | 12 |
| Gloomhaven | 5 дней назад | 54 | 4 игрока | 150 мин | Поражение | 6 | 27 |
| Brass: Birmingham | 2 недели назад | 18 | 2 игрока | 60 мин | Победа | — | 8 |
| Terraforming Mars | 3 недели назад | 27 | 2 игрока | 110 мин | Победа | — | 14 |

### Состояния карточки

1. **Недавно играли** — зелёный badge.
2. **Играли несколько дней назад** — warning badge.
3. **Давно не играли** — нейтральный badge.
4. **Ни разу не играли** — нейтральный badge «Ещё не играли», значение партий
   равно `0`.
5. **Нет изображения** — градиентный placeholder, сохраняющий контраст текста.

Hover поднимает яркость изображения и границы, но не меняет геометрию карточки.
Focus-visible показывает контрастный outline вокруг всей кликабельной области.

## 6.4 Карточка «Добавить игру»

Последней видимой ячейкой сетки отображается action-card:

```text
                 ┌────────┐
                 │   +    │
                 └────────┘
               Добавить игру
```

- размеры совпадают с обычной `CollectionCard`;
- прозрачная или базовая поверхность, пунктирная граница
  `--border-default`, radius 12 px;
- контент выровнен по центру обеих осей;
- знак «+» расположен в круге 64–72 px с фоном `--accent-soft`;
- подпись и знак используют `--accent-primary`;
- вся плитка является одной кнопкой и открывает `/items/new`;
- hover усиливает границу и фон, focus-visible показывает outline.

Плитка присутствует после последней карточки текущего набора и не учитывается в
счётчиках вкладок или пагинации.

## 6.5 Pagination

Для MVP использовать pagination:

- 24 карточки на страницу;
- кнопки предыдущая/следующая;
- номер страницы;
- URL query params.
- pagination располагается под сеткой и не занимает одну из её ячеек;
- при наличии следующей страницы action-card остаётся последней видимой плиткой
  после игровых карточек.

```text
/collection?page=2&type=game&sort=lastPlayed
```

## 6.6 Responsive toolbar

- при ширине, на которой строка перестаёт помещаться, поиск занимает отдельную
  первую строку;
- вкладки допускают горизонтальный scroll без переноса текста;
- сортировка и кнопка добавления остаются во второй строке;
- на mobile primary action может быть icon-only кнопкой с доступным
  `aria-label="Добавить игру"`;
- карточки и action-card используют одинаковые правила перестроения сетки.

# 7. Карточка элемента коллекции

Route:

```text
/collection/:itemId
```

Карточка собственной игры — рабочий экран владельца. Она должна помогать быстро добавить партию, проверить личное состояние игры и перейти к связанным данным. Личные данные и активность имеют больший визуальный приоритет, чем длинная справочная информация.

Основные принципы:

- главное действие — «Добавить партию»;
- личные и справочные данные редактируются раздельно;
- длинное описание, механики, категории и авторы вынесены во вкладку «Подробнее»;
- сложность игры, отдельные рейтинги BGG, Tesera и Nastolio, а также ссылки на эти источники остаются видимыми в hero;
- обзор содержит короткие сводки, полные списки открываются во вкладках;
- место хранения на карточке не показывается.

---

## 7.1 Верхняя навигация

Над hero-блоком расположить компактную кнопку возврата:

```text
← Моя коллекция
```

- ссылка возвращает в коллекцию с сохранёнными фильтрами и позицией прокрутки;
- промежуточный breadcrumb «Игры» и повтор названия игры не показывать;
- доступное название ссылки: `Вернуться в мою коллекцию`.

---

## 7.2 Hero

Desktop-компоновка:

```text
┌────────────┬─────────────────────────────────┬──────────────────────────────┐
│            │ Spirit Island [Базовая игра]    │ [+ Добавить партию]  […]    │
│ cover      │ Кооперативная защита острова    │                              │
│ 176–200 px │ 1–4 игрока · 90–120 минут       │ Наличие    В коллекции       │
│            │ Сложность 4.1 / 5               │ Статус     Активна           │
│            │ BGG 8.3 ↗ · Tesera 8.6 ↗        │ Моя оценка ★★★½☆            │
│            │ Nastolio 8.2 ↗                  │ Избранное  ♥ · теги          │
└────────────┴─────────────────────────────────┴──────────────────────────────┘
```

- левая колонка — квадратная обложка 176–200 px, `object-fit: cover`, radius 8–10 px;
- центральная колонка — название, краткий контекст, основные параметры и рейтинги источников;
- правая колонка — действия и компактная панель личного состояния;
- рекомендуемая grid-сетка: `minmax(176px, 200px) minmax(320px, 1fr) minmax(300px, 380px)`;
- gap между колонками — 24–32 px;
- при отсутствии обложки показывать fallback с названием и иконкой типа элемента.

### Публичные данные

Порядок элементов в центральной колонке:

1. Название игры и badge типа на одной строке. Пример типа: «Базовая игра».
2. Короткое описание или подзаголовок.
3. Диапазон количества игроков и длительность партии.
4. Сложность игры в формате `значение / 5`.
5. Отдельные рейтинги и ссылки BGG, Tesera и Nastolio.

Возраст, категория, жанр и механики в hero не выводятся. Они доступны во вкладке «Подробнее».

Рейтинги источников:

```text
BGG       8.3 / 10  ↗
Tesera    8.6 / 10  ↗
Nastolio  8.2 / 10  ↗
```

- не рассчитывать общий или средний рейтинг по источникам;
- каждый источник имеет собственное название, значение и внешнюю ссылку;
- ссылка ведёт непосредственно на страницу игры в соответствующем сервисе и открывается в новой вкладке;
- доступное название ссылки включает источник и игру, например `Открыть Spirit Island на BoardGameGeek`;
- если рейтинг отсутствует, но ссылка существует, показывать название источника и иконку внешней ссылки без значения;
- если отсутствуют и рейтинг, и ссылка, строку источника скрывать;
- ошибка одного провайдера не должна скрывать данные остальных;
- сложность визуально отделяется от рейтингов и не воспринимается как ещё одна пользовательская оценка.

### Личные данные

Правая панель содержит:

```text
Наличие         [В коллекции⌄]
Статус          [Активна⌄]
Моя оценка      ★★★½☆
Избранное       [♥]
Теги            Соло · Стратегия

[Редактировать личные данные]
```

- наличие и статус — разные поля;
- наличие определяет принадлежность элемента коллекции;
- допустимые статусы: «Активна», «На продажу», «Продана», «Архивирована»;
- статус «На продажу» доступен только для игры в коллекции;
- личная оценка — интерактивные 5 звёзд с половинными значениями;
- избранное переключается отдельной icon-button;
- показывать до трёх пользовательских тегов, остальные сворачивать в `+N`;
- место хранения не показывать;
- подписи образуют левую колонку, значения — правую;
- изменение личных данных не должно открывать форму справочных данных.

### Действия

Главная кнопка:

```text
+ Добавить партию
```

- всегда видима в hero для активной игры;
- открывает общую форму добавления партии с заранее выбранной игрой;
- после сохранения обновляет последние партии и агрегаты без полной перезагрузки страницы;
- для архивированной игры недоступна и сопровождается пояснением.

Overflow menu содержит только вторичные действия:

- редактировать личные данные;
- редактировать справочные данные;
- открыть полную справочную информацию;
- отметить «На продажу» или вернуть в активные;
- архивировать;
- удалить из коллекции.

«Удалить из коллекции» и «Удалить игру» — разные действия. Для потенциально разрушительных действий обязательны подтверждение, описание последствий и безопасный способ отмены, если он поддерживается.

---

## 7.3 Личная оценка

Внутреннее значение личной оценки остаётся целым числом от 1 до 10, а в интерфейсе отображается пятью звёздами с шагом в половину звезды:

```text
1 балл   = 0.5 звезды
7 баллов = 3.5 звезды
10 баллов = 5 звёзд
```

- количество звёзд рассчитывается как `personalRating / 2`;
- поддерживаются полная, половинная и пустая звезда;
- редактирование предлагает десять значений с шагом в половину звезды;
- должна быть возможность очистить оценку;
- control реализуется как доступная группа из десяти radio-значений;
- клавиши стрелок изменяют оценку на 1 балл;
- screen reader получает числовое значение, например `Личная оценка: 7 из 10`.

---

## 7.4 Tabs

Панель вкладок располагается сразу под hero-блоком и отделяется нижней границей.

```text
Обзор  Партии (42)  Дополнения (3)  Фото (18)  Покупки (1)  Заметки (2)  Подробнее
```

- количество отображается в круглых скобках рядом с названием вкладки;
- активная вкладка использует `--accent-primary` для текста и нижнего индикатора;
- вкладка «Заметки» обязательна;
- механики, категории, авторы, издатели, характеристики и связи находятся во вкладке «Подробнее»;
- отдельную вкладку «Связи» разрешено показывать только при большом количестве связей;
- нулевой счётчик показывает фактическое значение `0`, если вкладка доступна;
- ряд вкладок допускает горизонтальную прокрутку без переноса.

URL должен хранить активную вкладку:

```text
/collection/:itemId?tab=plays
```

Допустимые значения: `overview`, `plays`, `expansions`, `photos`, `purchases`, `notes`, `details`.

---

## 7.5 Вкладка «Обзор»

Обзор содержит короткие owner-first сводки и не заменяет полные вкладки. На desktop используется не более трёх колонок:

```text
┌──────────────────┬──────────────────────┬──────────────────────┐
│ Моя коллекция    │ Последние партии     │ Покупка / предзаказ  │
├──────────────────┼──────────────────────┼──────────────────────┤
│ Заметки          │ Дополнения           │ Фотографии           │
└──────────────────┴──────────────────────┴──────────────────────┘
```

Рекомендуемые пропорции CSS Grid: `1fr 1.25fr 1fr`. Все панели используют общий компонент `Panel`, одинаковые gaps и выравниваются по верхнему краю. Заголовки панелей набираются компактным uppercase-текстом.

### «Моя коллекция»

- дата добавления в формате `DD.MM.YYYY`;
- последняя партия;
- всего партий;
- победы / поражения;
- средняя длительность;
- любимое количество игроков, только если данных достаточно;
- часто играющие партнёры, только если данных достаточно.

Панель завершается secondary-кнопкой во всю доступную ширину: «Посмотреть статистику игры».

Метрики без достаточного количества данных не показывать. Не заменять их нулевыми или вымышленными значениями.

### «Последние партии»

- показать до трёх последних партий от новой к старой;
- строка содержит дату, количество игроков, длительность и badge результата;
- дополнительно показывать счёт и сценарий, если они заполнены;
- строка открывает просмотр или редактирование партии;
- результат «Победа» использует success-вариант, «Поражение» — danger-вариант;
- внизу — ссылка «Все партии (N)» с chevron.

Empty state:

```text
Вы ещё не играли в эту игру.
[Добавить первую партию]
```

### «Покупка / предзаказ»

Третья колонка содержит до двух независимых условных панелей.

Покупка:

- магазин;
- дата покупки;
- итоговая стоимость с валютой;
- количество покупок, если их несколько;
- ссылка на историю покупок.

Активный предзаказ:

- название заказанного элемента;
- status badge;
- ожидаемая дата;
- магазин;
- действие «Изменить дату».

Если покупки или активного предзаказа нет, соответствующую панель не показывать. Если обе панели отсутствуют, соседняя панель может занять освободившееся место.

### «Заметки»

- показать последнюю заметку не более чем в 4 строки;
- показать дату последнего изменения;
- добавить ссылку «Все заметки (N)»;
- при отсутствии заметок показать компактный empty state с действием «Добавить заметку».

### «Дополнения»

- показать до трёх дополнений;
- строка содержит квадратную миниатюру, название и status badge «Есть»;
- внизу — ссылка «Все дополнения (N)» с chevron;
- если дополнений нет, показать компактный empty state.

### «Фотографии»

- показать до четырёх превью с одинаковой высотой и `object-fit: cover`;
- последним элементом — bordered-кнопку «Добавить фото» с иконкой плюса;
- при переполнении ряд прокручивается горизонтально;
- клик по превью открывает просмотр фотографии;
- при отсутствии фотографий оставить кнопку добавления и показать компактное пояснение.

---

## 7.6 Вкладка «Подробнее»

Вкладка содержит справочную информацию, которая не нужна для ежедневного owner-сценария:

1. Полное описание.
2. Характеристики:
   - рекомендуемый возраст;
   - год выпуска;
   - язык;
   - вес игры;
   - размер коробки.
3. Механики и категории.
4. Дизайнеры, художники и издатели.
5. Связи с другими элементами.
6. Внешние идентификаторы и ссылки.

Рейтинги и ссылки BGG, Tesera и Nastolio остаются в hero; во вкладке «Подробнее» их повторять не требуется.

---

## 7.7 Раздельное редактирование

### Личные данные

Форма «Редактировать личные данные» изменяет только:

- наличие;
- статус;
- личную оценку;
- избранное;
- пользовательские теги;
- заметки.

### Справочные данные

Форма «Редактировать справочные данные» изменяет только:

- название и описание;
- тип и характеристики;
- механики и категории;
- дизайнеров, художников и издателей;
- изображения;
- внешние ссылки и идентификаторы.

Нельзя смешивать обе группы полей в одной форме или сохранять их одним неявным действием.

---

## 7.8 Состояния и обратная связь

### Loading

- skeleton для hero, личной панели, вкладок и overview-панелей;
- кнопки изменения данных недоступны до загрузки необходимых данных;
- не заменять всю страницу глобальным spinner.

### Empty

Предусмотреть отдельные состояния для отсутствующих:

- партий;
- дополнений;
- фотографий;
- покупок;
- предзаказов;
- заметок;
- рейтингов и ссылок внешних источников;
- обложки.

Empty state должен предлагать действие только там, где пользователь может устранить пустоту.

### Saving и error

- изменение оценки, избранного и статуса показывает локальный saving state;
- при успехе обновляется только соответствующая часть страницы и показывается toast;
- при ошибке возвращается предыдущее значение и доступно повторное действие;
- ошибка одной overview-панели не блокирует остальные;
- ошибка одного внешнего провайдера не скрывает рейтинги других провайдеров.

### Граничные случаи

Проверить:

- очень длинные названия игр;
- длинные пользовательские теги;
- длинные названия магазинов и имена участников партий;
- отсутствующие или частичные внешние данные;
- статусы «На продажу», «Продана» и «Архивирована»;
- доступность и пояснение действий для каждого статуса;
- 0, 1 и 100+ партий;
- 0 и большое количество фотографий, заметок и дополнений.

---

## 7.9 Адаптивность

Tablet:

- hero перестраивается в две колонки: обложка и публичные данные сверху, действия и личные данные — на всю ширину ниже;
- overview становится двухколоночным;
- рейтинги источников допускают перенос строк.

Mobile:

- навигация, hero и overview располагаются в одну колонку;
- обложка занимает доступную ширину с ограничением `max-width: 320px`;
- панель личных данных располагается после публичных данных;
- кнопка «Добавить партию» занимает всю ширину;
- рейтинги BGG, Tesera и Nastolio располагаются отдельными строками и остаются видимыми;
- вкладки и фотографии используют горизонтальный scroll;
- панели overview идут последовательно: «Моя коллекция», «Последние партии», «Покупка / предзаказ», «Заметки», «Дополнения», «Фотографии».

---

## 7.10 Accessibility

- вкладки используют `role="tablist"`, `role="tab"` и `aria-selected`;
- вкладки управляются клавишами стрелок, Home и End;
- рейтинг с половинными звёздами полностью доступен с клавиатуры;
- подписи BGG, Tesera и Nastolio нельзя заменять одними логотипами;
- каждая внешняя ссылка имеет доступное название и визуальный признак перехода;
- результат партии и статус не кодируются только цветом;
- icon-only кнопки имеют `aria-label`;
- focus-visible не обрезается контейнерами и горизонтальным scroll;
- минимальная интерактивная область — 40×40 px.

# 14. Адаптивность

# 14.1 Tablet: 768–1199 px

- sidebar сворачивается до 72 px;
- подписи навигации скрываются;
- `powered_by_bgg.webp` остаётся внизу sidebar, уменьшается до 48 px по ширине и не обрезается;
- dashboard grid становится 2-колоночной;
- collection cards: минимум 220 px;
- таблицы могут переходить в compact rows.

---

# 14.2 Mobile: до 767 px

Sidebar заменяется:

- верхним app bar;
- bottom navigation на 4–5 основных разделов;
- дополнительные пункты в меню.

Главная страница:

- одна колонка;
- панели располагаются вертикально;
- горизонтальные списки карточек допускают scroll-snap.

Collection:

- две карточки в ряд при ширине от 420 px;
- одна карточка при меньшей ширине.

Modal:

- превращается в bottom sheet или full-screen dialog.

Таблицы:

- заменяются карточками;
- вторичные колонки скрываются;
- действия доступны через overflow menu.

# 19. Definition of Done для вёрстки

Страница считается готовой, когда:

- визуально соответствует тёмному dashboard-стилю;
- работает на desktop, tablet и mobile;
- не ломается на длинном контенте;
- содержит loading, empty и error state;
- доступна с клавиатуры;
- компоненты переиспользуются;
- нет жёстко зашитых данных внутри UI-компонентов;
- все фильтры и вкладки имеют интерактивные состояния;
- модальные формы валидируются;
- URL отражает основные фильтры и активные вкладки;
- TypeScript не содержит `any`;
- в sidebar нет профиля пользователя, а внизу показан `powered_by_bgg.webp`;
- интерфейс можно подключить к реальному API без переписывания разметки.
