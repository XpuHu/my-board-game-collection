# Board Game Collection Manual-First Tasks

**Версия:** 3.0  
**Дата:** 2026-07-09  
**Статус:** Draft  

Этот план заменяет внешний поиск как основной сценарий. На текущий момент нет рабочих API-токенов для внешних каталогов, поэтому приложение должно быть полностью полезным в ручном режиме. BGG и Tesera считаются необязательными интеграциями, которые не должны блокировать создание игр, партий, wishlist, предзаказов, статистику и backup.

---

# 1. Проверка выполнения старого плана

## Реализовано

* Этап 0: Next.js, TypeScript, базовый `src`, Tailwind/UI-компоненты, lucide, lint/typecheck/test scripts.
* Этап 1: Prisma + SQLite, основные модели, индексы, seed системных типов, DTO и Zod-схемы.
* Этап 2: общий API layer, пагинация, обработка ошибок, item/collection/wishlist services.
* Этап 3: основной layout, навигация, API client, loading/empty/error/toast/confirmation states.
* Этап 4: список коллекции, компактная карточка коллекции, редактирование `UserItem`, фильтры.
* Этап 5: API партий, форма добавления партии, история партий, редактирование и удаление партий.
* Этап 6: API предзаказов, список предзаказов, изменение ожидаемой даты с `PreorderEvent`.
* Этап 8: список wishlist, подробная карточка, добавление wishlist item в коллекцию, предзаказ из wishlist.
* Этап 11: Statistics service/API и страница статистики.
* Этап 12: JSON export/import с отчетом и пропуском дублей.
* Часть Этапа 13: unit/API/component-smoke tests. Текущая проверка: `npm test` проходит, 19 tests passed.

## Частично реализовано

* Этап 7: provider interface, BGG provider, Tesera provider, внешний поиск, внешний импорт и ручной fallback есть, но UX все еще ведет пользователя через внешний поиск первым шагом.
* Этап 9: BGG play provider, sync service и UI есть, но без API-токена этот сценарий нельзя считать рабочим.
* Этап 10: справочная синхронизация есть, но зависит от внешних provider-данных и поэтому сейчас должна быть отключена или переведена в ручной режим.
* Этап 13: есть unit/API/component-smoke tests, но нет полноценных E2E и компонентных интерактивных тестов.

## Не соответствует текущим условиям

* Старый план считает BoardGameGeek основным источником для поиска, импорта и sync. Это больше не годится без токена.
* Экран добавления игры должен начинаться с ручной формы, а не с поиска BGG.
* Ошибки BGG/Tesera не должны попадать в основной пользовательский сценарий создания игры.
* Настройки BGG sync должны быть скрыты, помечены как недоступные или переведены в режим "только после настройки токена".
* Справочные данные, изображения, ссылки, категории, механики, издатели и авторы должны редактироваться вручную.

# 2. Новые принципы MVP

* Ручной ввод является основным и обязательным путем создания данных.
* Внешние провайдеры не участвуют в критическом пути.
* `Item` остается основной справочной сущностью.
* `UserItem` остается пользовательским состоянием: owned, wishlist, status, location, rating, notes, tags.
* Все поля, которые раньше ожидались из BGG/Tesera, должны быть доступны для ручного создания или редактирования.
* Любая внешняя интеграция должна быть feature-flagged или визуально помечена как недоступная без токена.
* Backup/import должен быть надежным способом переноса данных между локальными установками.

# 15. Первый manual-first вертикальный срез

1. `/items/new` открывает ручную форму сразу.
2. Пользователь создает игру с базовыми справочными полями.
3. Игра добавляется в collection или wishlist без внешних запросов.
4. Пользователь добавляет партию к созданной игре.
5. Пользователь оформляет предзаказ из wishlist.
6. Пользователь экспортирует JSON backup.

После этого приложение остается полезным даже при полном отсутствии API-токенов и внешней сети.

## Итерация 1. Manual-first вход

Цель: пользователь может добавить игру без внешних запросов.

Реализовать:

1. M-0001: переделать `/items/new` в экран "Добавить игру".

Проверить:

* создать игру вручную;
* добавить игру в коллекцию;

## Итерация 11. Отложенная внешняя интеграция

Цель: подготовить BGG/Tesera к будущему, но не возвращать их в критический путь.

Реализовать только после появления токенов:

1. M-0603: будущий BGG client с `BGG_APPLICATION_TOKEN`.
2. M-1001: BGG search/sync через `Authorization: Bearer ...`.
3. M-1002: Tesera как optional best-effort provider.
4. Rate limiting и cache для внешних запросов.

Проверить:

* ручной MVP работает при выключенных provider flags;
* включение provider flags не меняет ручные сценарии;
* ошибки provider-ов возвращаются как warnings или понятные provider errors.

## Рекомендуемый первый pull request

Первый PR должен быть маленьким, но сразу полезным:

1. `/items/new` открывает ручную форму сразу.
2. Ручная форма поддерживает designers, artists, link URL и image URL.
3. `EXTERNAL_PROVIDERS_ENABLED=false` отключает внешний поиск без сетевых запросов.
4. `BGG_SYNC_ENABLED=false` отключает BGG sync в API и UI.
5. Добавлены тесты на manual create и disabled external providers.
